# Следующий спринт v0.3.3 — доказательный READ ONLY коннектор

## P0: финансовая правда

1. Получить настоящие выгрузки от WB #1, WB #2 и Ozon #1 без отправки API-токенов в чат, с согласия собственников. Для каждой выгрузки зафиксировать версию API/файла, период, валюту, контрольные суммы и описание статуса операции.
2. Подключить **первую одну** площадку READ ONLY и сопоставить конкретный финансовый отчёт с `ledger` по `provider+store+source_id+line_id`, не только `order_id`. Вторая площадка — после сверки первой.
3. Реализовать импорт raw событий (append-only), cursor/watermark, idempotent upsert/reconciliation и обработку поздних корректировок. Не складывать продажи, начисления и выплаты в одну выручку.
4. Отдельно считать источники рекламных расходов и возвращаемых/выкупленных продаж; не смешивать рекламные атрибутированные и общие заказы.
5. Завести cost by purchase batch и сводную учётную модель P&L/ДДС; связывать возвраты с исходным заказом.

## P0: безопасность интеграций

6. Разрешить запросы только строго заданным read-only API methods из документированного списка. Scope минимальный, никаких price/ads write endpoints.
7. Проверять stop-флаги **перед каждым** исходящим запросом, а не только перед постановкой в очередь; ограничить сетевые таймауты, повторные запросы и rate limits по ключу и методу.
8. Инцидент-тест: во время синхронизации stop global/platform/store/token, подтвердить отсутствие новых dispatches после стопа.
9. Не логировать Authorization/API-Key; журнал держать с клиентскими ID и метаданными без коммерческих/персональных значений.

## P1: SaaS-направление

10. Прототип пользователей/ролей owner/manager/auditor и серверной авторизации на каждой бизнес-сущности в отдельном PostgreSQL staging (без внешних клиентов до QA).
11. План миграции локального vault к KMS; автоматический onboarding с отдельной ролью владельца ключа, MFA и revoke.
12. Event-based AI CFO только после подтверждения финансовых Evidence Packs и тестов на prompt injection/financial hallucinations.

## Финансовые gates

- Сверка внешнего отчёта с raw event ledger и итогами: расхождения объяснены или блокируют P&L.
- Дубликаты и коррекции обрабатываются детерминированно.
- Потенциальный/сценарный/фактический эффект нигде не смешивается.
- Результат первого реального магазина проверен по строчкам человеком.
- Точность каждой цифры может быть воспроизведена без LLM и без доверия к сообщению агента.
