# v0.3.6 — Financial Reconciliation (следующий этап)

## P0

1. Схема реальных финансовых начислений WB/Ozon, версия контракта и quarantine новых типов без автоматического распознавания.
2. Ozon: актуальные отчёты реализации (новые методы, опубликованы 18.11.2026), справочник типов и сверка по отправлениям.
3. WB: список отчётов, детализация по ID и по периоду; состав полей, календарь Москвы, лимиты, rrdId и состав денежных строк.
4. Операционный журнал источников с source-event-id, контрольной суммой, историей схем и независимой сверкой итогов.
5. Серверные правила: sale/return/storno/fee/storage/delivery/refund/other; отрицательные корректировки; неизвестный тип — карантин.
6. Историческая себестоимость и партии; отсутствие COGS блокирует net margin по SKU, но не UI как таковой.
7. Результат в UI: `Данные в процессе проверки`, `Расхождение`, `Сверено`, `Устарело`, `Частично загружено`.

## P1 / Production prerequisites

8. Real key canary только по отдельному разрешению пользователя и после проверки offline-runbook. После первых ответов создать безопасные обезличенные контрактные фикстуры.
9. Проверка доступности/стоимости WB API для сторонних сервисов, Ozon OAuth, партнёрских требований и хранения персональных данных в РФ.
10. Multi-tenant PostgreSQL / RLS, RBAC/MFA, KMS, распределённый quota/kill, очередь задач; не выносить текущий localhost-сервер в интернет.

## Gate

- 100% контрольных сумм тестовых синтетических отчетов совпадает с независимым эталоном.
- Все неизвестные начисления попадают в quarantine, а не в прибыль.
- Система не удваивает суммы при пересечении отчетов/переимпорте.
- Нет использования токенов без двух разрешений; отключение немедленно блокирует новые запросы.
