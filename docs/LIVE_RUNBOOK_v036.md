# Ручной этап после v0.3.6

Этот релиз не выполняет canary и не разрешает его автоматически. Ключи нельзя присылать в чат. Унаследованный guarded transport остаётся выключенным по умолчанию; API staging не публикуется как прибыль.

1. На локальном Mac пройти тесты, проверить восстановление резервной копии базы/vault, дату окончания и минимальные права ключа, отсутствие публичного порта. Убедиться, что оператор разрешает именно один кабинет и один короткий период.
2. Получить отдельное явное разрешение владельца на реальный READ ONLY тест. Текущая задача разрешает разработку v0.3.6, а не доступ к реальным кабинетам.
3. Сначала получить актуальную OpenAPI-схему/официальные request/response; для WB разобрать каждый денежный компонент и способ отделения продаж, возвратов, комиссий, выплат и корректировок. Не использовать `forPay` одновременно как выручку и как сумму после комиссии.
4. Для Ozon проверить каталог types, by-day, postings и новые реализации; установить точные тела запросов, пагинацию, необходимые права и статусы файлов. Не скачивать файл по произвольному URL из ответа: нужен отдельный host allowlist и ограничения размера/типа/редиректов.
5. Прежняя двухступенчатая защита v0.3.5: явный environment opt-in и TTL/лимитированный permit для конкретного store/provider/credential/path. Изменение stop/revoke/rotate/expiry аннулирует разрешения. Новые маршруты v0.3.6 в реальную allowlist не включены; ReportLab не может стать живым транспортом.
6. Первые ответы — только staging, с разрешённой политикой PII/retention. Создать обезличенные фикстуры, проверить поля/типы/терминальный cursor и независимые итоги с выгрузкой ЛК. После этого написать версионный нормализатор и контрактные тесты; изменение live allowlist — отдельная проверяемая правка.
7. Первая сверка — один WB; потом отдельно второй WB и Ozon. Не включать массовый backfill или публичный сервер.
8. При несовпадении схемы/сумм/полномочий — остановить, сохранить минимизированные диагностические хеши, не признавать прибыль и не очищать карантин автоматически.

Практические команды preflight, короткого permit и аварийной остановки сохранены в `docs/LIVE_RUNBOOK_v035.md`. Они описывают будущую ручную процедуру, а не выполненный тест. При утечке ключ отозвать также на стороне площадки; локальный стоп не отзывает внешний токен.
