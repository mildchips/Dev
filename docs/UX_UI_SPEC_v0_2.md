# AI Profit Office — UX/UI спецификация v0.2

**Дата:** 18.11.2026. **Статус:** целевой UX и демонстрационный прототип, не действующий SaaS.

## 1. Принципы интерфейса
1. **Opportunity first, not profit dashboard:** первый экран отвечает «где теряю деньги?», «какая уверенность?», «что сделать сегодня?». Текущая прибыль — контекст, не заголовок продукта.
2. **Три режима, единые расчёты:** `Начинаю`, `Контролирую`, `Развиваю`. Смена режима бесплатна и обратима. Тариф не привязан к сложности языка.
3. **Progressive disclosure:** новичку сначала одно понятное действие; финансист получает таблицы, детали источников и фильтры; оптимизатор — сценарии и портфель возможностей.
4. **Provenance by design:** рядом с каждой суммой период, тип (разово/в месяц), статус (гипотеза/подтверждено/измерено), источник и дата обновления.
5. **No phantom profit:** потенциальный резерв не равен уже полученным деньгам, рекламная атрибуция не равна приросту продаж, разовые возвраты не складываются с ежемесячной экономией.
6. **Agent-safe:** по умолчанию read-only; предложения изменять цены/ставки/остатки — только гипотезы, никакого автоматического исполнения.
7. **Manager privacy:** бесплатный Manager Workspace — только с явным доступом по каждому магазину; публичная превью-карточка обезличена.
8. **Accessibility and mobile first for daily alerts:** контрастный текст, крупные цели на кнопках, клавиатурная навигация, отсутствие зависимости от цветовой кодировки.

## 2. Дизайн-система (перенос принципов проекта «Биржа»)
- Dark mode by default, фон `#0B1110`, подложка `#101815`, карточки `#17211D`, границы `#2C3B34`, типографика `#E8EEE9`, вторичный `#9AA8A0`.
- Semantic accent Emerald `#55BE8A`, приглушённый gold `#C7A56B` для прогнозных/неподтверждённых резервов; красный `#E18A89` только для ошибок и подтверждённых негативных статусов.
- Никаких насыщенных фиолетовых градиентов, стеклянных карточек ради украшения или агрессивных анимаций.
- 8px spacing system, max content width 1440px, 240px sidebar, mobile bottom navigation, вёрстка от 360px, адаптивные таблицы.
- Табличные финансовые цифры в tabular numerals; значения в рублях показывать с пробелами, период и базу раскрывать в tooltip / деталях.

## 3. Общая информационная архитектура
**Global:** Магазин, WB/Ozon/оба, обновление данных, состояние полноты, переключатель режима, тариф, профиль, помощь.
**Navigation:** Обзор, Возможности, План действий, Финансовые причины, AI CFO, Данные/подключения, Для менеджера (по роли), Настройки.
**Persistent:** уведомления об изменениях, хлебные крошки, «Есть данные только для части SKU», «Почему цифры могут быть неполными».
**Opportunity detail:** проблема → размер/период/уровень уверенности → объяснение → источник → возможное действие → риски → статус → эффект после внедрения.
**No insight state:** «Мы не нашли доказанных потерь за выбранный период» или «не хватает данных» вместо выдуманной «экономии».

## 7. Агентное взаимодействие
- Основной UI — финансовые карточки, а не чат; AI CFO отвечает на вопросы поверх Evidence Packs.
- Любой агент возвращает structured output: `problem_id, source_refs, reason, confidence, affected_skus, amount_type, estimate_interval, next_action, risk_flags`.
- LLM не может менять расчёт, состояние verified/measured, финансовые ограничения; только объяснять и предлагать.
- Перечень агенто-сценариев: Finance, Ads, Logistics, Pricing, Inventory, Risk. Один оркестратор; нет дорогих фоновых LLM-циклов без событий.

## 8. Важные экраны и состояния
1. **Welcome + selector** — «Что вам ближе?» (можно пропустить, поменять позднее).
2. **Connect** — выбрать площадку, безопасная проверка прав, либо загрузка файлов.
3. **COGS setup** — себестоимость SKU как источник, дата действия, пропуски и стоимость логистики, если доступна.
4. **Data Health** — «полно/частично/ошибка», без подмены неизвестного нулём.
5. **Home** — 3 действия/диагностика/оптимизация согласно режиму.
6. **Opportunities** — сортировка по ожидаемому чистому эффекту и статусу.
7. **Evidence drawer** — исходные строки, формула, влияние и ограничения.
8. **Action plan** — ответственный, дата, шаги, внедрение, измерение.
9. **AI CFO** — вопросы и ссылочные ответы; offline/usage-limit fallback.
10. **Pricing** — сравнение 990 / 1 990 / 2 990 по реальным лимитам, без приравнивания уровня знаний к цене.
11. **Manager Workspace** — портфель разрешённых магазинов, приглашения, share, атрибуция referrals.
12. **Settings & Trust** — отключение API, управление consent, экспорт, удаление, журнал действий.

## 9. UX-тестирование
- Модерируемые прототипные тесты: минимум 5 респондентов на каждую персону в начале, затем ≥10 на gate Private Alpha.
- Задания новичку: отличить «потенциал» от «экономии», пройти мастер себестоимости, найти первое действие.
- Финансисту: открыть первичную операцию, проверить период и формулу, найти причину изменения маржи.
- Оптимизатору: сравнить два сценария с риском, отклонить заведомо опасный, поставить задачу и найти метод измерения.
- Менеджеру: получить разрешение, подготовить обезличенную карточку, поделиться с владельцем и отозвать доступ.
- Accessibility: WCAG AA для критических состояний как целевой стандарт; клавиатура, экран 360px, tabular numbers.

## 10. Прототип
`prototype/index.html` — автономный кликабельный mockup без серверов/API/сохранения и реальных расчётов. Все кейсы вымышленные. Предназначен для обсуждения UX, не для продаж как доказательства эффективности.
