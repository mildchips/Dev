# AI Profit Office v0.3.5 — guarded READ ONLY: безопасный регламент

**Дата:** 18.11.2026. **Статус:** код live-транспорта реализован, реальные запросы НЕ выполнялись, live по умолчанию выключен.

## Условия запуска

- Только локальная машина оператора, никакого размещения текущего web-сервера в интернете.
- Только личные магазины (доступ на основании законного разрешения) и только одно короткое окно финансовых данных на первом тесте.
- Токены вводятся исключительно через скрытый терминальный ввод `integration_cli add` или `rotate`, не через чат, `.env`, URL, скриншоты и логи.
- У Ozon срок действия ключа должен быть известен и внесён в локальную запись; фактическое право доступа определяется **только при live-вызове**.
- Полный текущий offline suite и smoke должны пройти до любого допуска.
- После включения live все ответы сохраняются в **staging/quarantine**, а не в финансовый реестр и не попадают в расчёт прибыли.

## Безопасный порядок, когда пользователь явно решит протестировать

**СЕЙЧАС ЭТО НЕ ДЕЛАТЬ.** Порядок опубликован для будущего ручного теста.

1. Выключить VPN и прокси, если они вмешиваются в TLS; убедиться, что выполняется работа с доверенной сети. Не отключать TLS-проверку.
2. Остановить публичные/внешние веб-сервисы, сделать backup базы и vault. Проверить права файлов 0600 и каталога 0700.
3. Создать реальный магазин в локальном приложении и добавлять токены исключительно через `python -m app.integration_cli add` (без аргументов с секретом).
4. Для Ozon зафиксировать дату окончания API-ключа, проверив её в личном кабинете: `python -m app.live_cli set-expiry --credential CRED_UUID --date YYYY-MM-DD`.
5. Выбрать **один** магазин и маршрут. Сначала только офлайн-проверка:

```bash
python -m app.live_cli preflight --credential CRED_UUID --store STORE_UUID --provider Ozon
# Либо --provider WB
```

6. Только после явного решения владельца вручную включить процесс (это делает возможными обращения по сети):

```bash
export AI_PROFIT_ALLOW_LIVE=EXPLICIT_READ_ONLY
python -m app.live_cli arm --credential CRED_UUID --store STORE_UUID --provider Ozon --max-requests 2 --minutes 10
# CLI отдельно потребует подтверждающую фразу. arm НЕ отправляет запросов.
```

7. Выполнить **один** canary с малой глубиной (не делать сейчас):

```bash
python -m app.live_cli canary --credential CRED_UUID --store STORE_UUID --provider Ozon --day YYYY-MM-DD --max-pages 1
# Для WB:
python -m app.live_cli canary --credential CRED_UUID --store STORE_UUID --provider WB --from-date YYYY-MM-DD --to-date YYYY-MM-DD --max-pages 1
```

   `max-pages=1` может дать **ожидаемый статус неполного теста**, если есть следующая страница. Этот факт не является финальной финансовой сверкой. Не увеличивать объём без проверки первичного ответа и лимитов.

8. Немедленно выключить live-режим:

```bash
python -m app.live_cli disarm --credential CRED_UUID
unset AI_PROFIT_ALLOW_LIVE
```

9. Сверить структуру ответа, идентификаторы событий, курсоры, объём и итоги с выгрузкой той же даты. Ошибки схемы — quarantine, не «исправлять» финансовый результат догадками.

## Аварийные действия

- Для мгновенного запрета **новых** запросов из любого оператора: `./scripts/kill-all.sh` (работает при корректном указании тех же путей vault/database), затем `unset AI_PROFIT_ALLOW_LIVE`.
- Для точечной остановки: `python -m app.integration_cli stop --scope credential --id CRED_UUID` либо `--scope store --id STORE_UUID`, `--scope platform --id WB/Ozon`.
- После STOP все допуски на live-запросы затронутой области уничтожаются; при RESUME старые допуски не восстанавливаются.
- Если ключ подозревается в компрометации, `revoke --id` очищает локальные зашифрованные байты. Обязательно отозвать этот ключ и на маркетплейсе.
- Программная остановка не способна гарантированно отменить HTTP-запрос, уже переданный на площадку.

## Предохранители реализации

- Сеть выключена без точного значения переменной окружения.
- Разрешение выдается на конкретные `credential_id`, `store_id`, WB/Ozon и endpoint, действует до 30 минут и содержит бюджет максимум 10 сетевых попыток (обычно 2).
- Все попытки расходуют бюджет, включая ошибки и повторы.
- Запросы разрешены только к закреплённым HTTPS-хостам WB/Ozon. Редиректы запрещены, прокси из окружения не используются, TLS-проверка включена.
- При 401/403 ключ автоматически блокируется локально, а ответ провайдера не отображается.
- При 429 и 5xx — ограниченные повторы. Лимит WB моделируется 60 сек/магазин; Ozon 2 сек/магазин — **локальная консервативная настройка, не официальная универсальная квота**.
- Очередь и лимиты локальные (SQLite). Для публичного SaaS необходимы централизованные лимиты и kill-switch на уровне всех воркеров.

## Что пока отсутствует

Полноценные OAuth-интеграции, реальная авторизация прав ключа, подтвержденная схема Ozon, полный набор финансовых методов, production KMS, RBAC и проверенный 152-ФЗ-контур. Все это — условия будущего production, не свойства v0.3.5.
