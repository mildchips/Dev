# v0.3.8 — синтетический PostgreSQL staging

Проверка запускает PostgreSQL 17.7 в одноразовом Docker-контейнере с динамическим
портом на loopback. Контейнер и его анонимный том удаляются при остановке. Для
набора нужны доступ к локальному Docker, образ из Docker Hub, Python 3.13 и pytest.
В v0.3.7 финансовое приложение и lab по-прежнему предназначены для локального
запуска. Публичный запуск v0.3.7 заблокирован.

```bash
uv --no-cache pip install --python .venv-3.13/bin/python -r staging_v038/requirements.txt
AIPO_RUN_PG_STAGING=1 .venv-3.13/bin/python -m pytest -q staging_v038/test_postgres.py
```

Образ закреплён версией и digest в тесте. Набор проверяет версию живого сервера.
Временные пароли генерируются при запуске. Доступ к Docker-демону следует считать
административным доступом к тестовой среде. Тест использует только синтетические
данные, а результаты изоляции относятся к двум таблицам, `stores` и `reports`.

| Роль PostgreSQL | Доступ в проверке |
|---|---|
| `aipo_migration` | Владеет БД, схемами и объектами миграции, администрирует memberships |
| `aipo_api` | Читает магазины и отчёты в рамках RLS. Владелец организации может создать магазин и изменить его название |
| `aipo_worker` | Читает в рамках RLS. При действующей роли owner/manager добавляет неизменяемый синтетический отчёт в доступный магазин |
| `aipo_backup` | Читает все строки двух синтетических таблиц через отдельные SELECT-политики |
| Bootstrap `postgres` | Создаёт роли, БД и фикстуры. Восстанавливает синтетический дамп в отдельную БД |

Контекст tenant/user устанавливается в транзакции. Пул сбрасывает состояние сессии
перед повторной выдачей соединения. Тесты проверяют один и тот же backend после
коммита, ошибки и намеренно оставленных параметров сессии. При READ COMMITTED
следующий запрос видит уже зафиксированный отзыв membership. Произвольный SQL от
имени runtime-роли может менять custom GUC, поэтому идентификаторы должен
передавать доверенный серверный код после проверки личности.

Контрольное восстановление проверяет `pg_dump` под backup-ролью и сравнивает
строки в отдельной БД того же инстанса. Memberships исключены из набора данных.
HA, WAL/PITR, потеря primary, независимое хранилище, отзыв вне откатываемого
снимка, повтор удаления и RPO/RTO требуют отдельного учения в целевом контуре.

Контейнер использует `--rm`. Для ручной остановки прерванного прогона сначала
проверьте ID контейнера, запущенного этим прогоном, через
`docker ps --filter label=aipo.scope=synthetic-v038`, затем выполните
`docker stop <ID>`. Проверки выполняются на синтетике в Linux или локальном
Docker. Результат каждого прогона содержит число проверок и ошибки.
