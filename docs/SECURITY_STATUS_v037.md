## Границы реализации

`app/server.py` продолжает слушать только localhost и обслуживает одного локального оператора. `saas_lab/server.py` — отдельный процесс на 127.0.0.1:8766. Их базы, cookie и маршруты независимы. Старые финансовые маршруты НЕ приобрели tenant security от добавления лаборатории. В лаборатории нет ввода токенов, финансовых файлов или сетевого gateway. Внешний API и LLM не подключались.

SQLite не защищает от администратора с доступом к файлу. Триггеры аудита защищают только штатный SQL-путь, не являются WORM. Все лабораторные транзакции сериализуются через BEGIN IMMEDIATE — это намеренная простая модель, не архитектура для 1000 клиентов. У очереди at-least-once delivery; exactly-once внешних действий не заявляется. Реальных внешних действий в lab нет.

Сессия живёт 30 минут; CSRF нужен для mutations; membership проверяется заново в транзакции. Доступ менеджера/аудитора после принятия приглашения действует 24 часа; лабораторное владение организацией — год. Восстановление пароля, смена владельца и редактирование membership не реализованы. После перезагрузки страницы нужно снова войти: CSRF не хранится в localStorage. Для нового инвайта учётную запись заранее создаёт локальный оператор. Повторное приглашение существующего участника отклоняется, включая отозванного: нет скрытого восстановления прав.

KMS: код `saas_lab/crypto.py` реализует AES-256-GCM, отдельный случайный DEK, AAD tenant/store/provider/version/key_id, wrap/unwrap через внедрённый интерфейс. Ошибка KMS прерывает операцию. Это библиотечный механизм, не production-vault: нет хранилища credential versions, привилегированного worker IAM, облачной ротации и memory zeroization Python. Фальшивый KMS используется только тестами. Нельзя подменять им рабочий KMS.

Резервирование лаборатории: пароль 16–256 символов, scrypt и AES-GCM, случайная соль/nonce, файл 0600, запрет перезаписи, максимум 64 MiB снимка. Пароль не сохраняется в архиве. Утрата пароля означает невозможность восстановления. Рабочие cookies и ссылки после restore не оживают; все организации остановлены до ручного resume; все делегаты отключены, чтобы старая копия не вернула отозванное membership. Владельцы/пароли берутся из снимка: для production нужен независимый recovery/revocation процесс. Снимок не содержит базу/ключи старого приложения. Для старого приложения сохраняется прежняя инструкция остановить приложение и скопировать всю `~/.ai_profit_office` в защищённое место.

## Проверка PostgreSQL до объединения

`deployment/postgres/001_rls_DRAFT.sql` — документированный dry-run с ROLLBACK, только stores/reports; он не исполнялся здесь. Не является полным schema migration. Сначала закрепить версию PostgreSQL, создать отдельные роли миграций/API/worker/backup. API не владеет таблицами и не получает BYPASSRLS/superuser/DDL. `SET LOCAL app.user_id/app.tenant_id` разрешён только серверу после проверки сессии, на каждую транзакцию; очистка пула обязательна. SQL injection с возможностью менять GUC остаётся отдельной угрозой. SECURITY DEFINER требует фиксированного search_path и минимальных EXECUTE grants.

Обязательные интеграционные проверки: отсутствие контекста; tenant A/B; scope менеджера; истёкшее/отозванное membership; SELECT/INSERT/UPDATE/DELETE; перенос store/tenant у существующей строки; FK/unique side channels; worker и экспорт; повторное использование pooled connection; backup без незаметной фильтрации RLS. Ни одного PASS для PostgreSQL этот релиз не заявляет.

Источники архитектуры: [PostgreSQL RLS](https://www.postgresql.org/docs/current/ddl-rowsecurity.html), [Yandex KMS envelope encryption](https://yandex.cloud/ru/docs/kms/concepts/envelope). Выбор облачного провайдера и тарифа ещё не сделан.
