# Следующий спринт — v0.3.1 / v0.4 (не реализовано)

## P0 — данные и правильная методология

1. Получить с разрешения владельцев 5–10 реальных выгрузок разных типов (WB: детализация реализации, логистика, вознаграждение, реклама; Ozon: продажи, начисления, реклама) и проверить версии схем на дату.
2. Для **одной** площадки создать доказательный адаптер, который отделяет sale / return / cost / payout и сохраняет первичный event-ID. Не объединять разные отчёты по одному order_id без проверки кратности.
3. Добавить cost revisions (`sku`, дата действия, партия, unit-cost) и корректный анализ маржи по дате продажи.
4. Сделать независимую реконсиляцию итога на двух разных источниках, статус расхождения и заблокированную «выгоду», если база не сверена.
5. Ввести period filters и детерминированную дедупликацию событий разных файлов и периодов.

## P1 — продукт и безопасность

6. Безопасные ролевая модель и авторизация: owner, manager, auditor, invites/revocations; тесты межмагазинного доступа по user identity, не только по store_id.
7. Согласовать data model событий с будущей API-интеграцией (sync cursor, quotas, watermark, append-only source events).
8. Переход к RAG/LLM объяснениям **только поверх проверенных Evidence Packs** с JSON-schema, тестами на финансовые галлюцинации и prompt-injection.
9. Собрать пользовательские UX-тесты по трём режимам, измерять time to first trusted value.
10. Создать техническую телеметрию стоимости импорта, CPU, числа LLM токенов, ошибок и поддержки на одного клиента.

## P1 — рыночная проверка

11. Уточнить позиционирование 100 000 ₽: где уместен квалификационный минимум оборота, какие слова рекламно и юридически безопасны. Без реальных кейсов не делать безусловных гарантий.
12. Проверить цену 990 / 1990 / 2990 ₽ на 10–20 действующих селлерах без подмены «интересно» фактом оплаты.
13. Протестировать привлечение через 10 действующих менеджеров (только с согласия собственников магазинов). Manager Workspace и публичная реферальная система — в отдельном релизе после RBAC.

## Gates перехода к Private Alpha

- Financial: подтверждённые модели данных для хотя бы одного типа отчётов; необъяснимых расхождений нет в тестовом наборе; COGS по датам не искажается.
- Evidence: любые суммы опираются на исходные строки, формулы и период; ложных утверждений о возвращённых деньгах нет.
- Security: авторизация, tenant isolation, тесты прав, аудит, удаление данных, базовое управление секретами.
- Commercial: не менее 5 реальных платежей/эквивалентных подтверждённых обязательств; измеряется повторное использование.
