# R02-PILOT · два клиента на PostgreSQL

25.11.2026. На базе Dev `9fee2ed` с миграцией R01 пройдены 29 проверок на
PostgreSQL 17.7. Команда:

```bash
AIPO_RUN_PG_STAGING=1 .venv-3.13/bin/python -m pytest -q staging_v038/test_postgres.py
```

В фикстуре у каждого клиента по два магазина; UUID магазина намеренно совпадают
между клиентами. Проверены выборки без фильтров, чужие INSERT/UPDATE/DELETE,
tenant-scoped FK, ограниченный менеджер, немедленный отзыв, повторное
использование того же PID после commit/rollback и сброс настроек сессии.
Пилот также выгрузил данные от backup-роли и сравнил восстановленные строки в
отдельной БД того же инстанса.

| Объект | Защита в этом пилоте |
|---|---|
| Синтетические stores и reports | FORCE RLS, scoped роли API/worker, отдельная политика backup |
| Членства | Прямой доступ ограничен ролью миграции и bootstrap. Runtime вызывает ограниченную проверку |
| Сессии, IdP-субъекты, инвайты | В пилоте отсутствуют |
| Finance contracts, schema observations, reports/sources, report events | Текущее финансовое приложение использует SQLite. Политики ещё нужны |
| Finance quarantine, controls, batches, costs, cost revisions, ledger | Нужны tenant-scoped ключи, RLS и тест миграционного паритета |
| Журнал, действия, reviews, сигналы и импорты | Нужны scoped чтение, запись и тесты на связанную сущность |
| Credentials, jobs, cursоры, stop, квоты, файлы и экспорт | Нужны отдельные роли, политики и проверки каждой операции |

GUC формирует только доверенный сервер в транзакции. RLS не защищает от
произвольного SQL от имени runtime. Проектирование нового API и интеграция
реального IdP остаются открыты.
