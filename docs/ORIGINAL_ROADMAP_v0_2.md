# Product Roadmap — 0.1 → 2.0

Стартовой датой плана считается 18.11.2026. Даты ориентировочные: переход только по прохождении gate, без фиктивного выполнения. Для каждого релиза фиксировать changelog, источники данных, версии алгоритмов, результаты тестов и открытые блокеры.

## Стадия 0 — Problem/Solution Discovery (18.11–08.12.2026)

### v0.1 — Strategy & Evidence (недели 1–2)
- ICP: активный селлер WB/Ozon с месячными продажами условно 150 тыс.–3 млн ₽, 10–300 SKU; менеджер, обслуживающий 2–10 магазинов, как отдельный канал дистрибуции. Диапазон — гипотеза.
- Определить карту зон потерь, финансовую онтологию, источники, 20 тестовых гипотез детекторов.
- 20 интервью: ≥10 владельцев и ≥10 действующих менеджеров; 10 обезличенных выгрузок по согласию; 5 конкурирующих сценариев сравнения.
- 2 лендинга/угла подачи с одним брендовым УТП: «100 000 ₽» для квалифицированного сегмента и «найдём конкретные потери» для остальных; не объявлять гарантию.
- Создать synthetic fixtures с известными потерями и спорными начислениями.
**Gate:** ≥8 из 20 интервью признают боль частой; ≥5 дают доступ к тестовому набору данных; ≥3 готовы оплатить тестовый доступ (высказанное намерение — НЕ платёж). Если нет — изменить ценностную гипотезу.

### v0.2 — Financial Ledger & Reconciliation (недели 2–5)
- Excel/CSV ingest для одной площадки (выбрать по полноте источников, не по бренду). Нормализация продаж, комиссии, логистики, возвратов, корректировок, рекламных затрат и себестоимости.
- Явный статус полноты данных; пробел себестоимости не подменять оценками в «факте».
- Реконсиляция totals с исходным отчётом, объясняемые расхождения, единицы, даты и НДС.
- Протокол версии схемы, правила, источника и периода.
**Gate:** на проверочной выборке 100% строк имеют происхождение; нет необъяснённых существенных расхождений; 0 двойного учёта в fixtures; сложные расхождения остаются заблокированными.

## Стадия 1 — Evidence MVP (декабрь 2026 — январь 2027)

### v0.3 — Opportunity Engine (недели 4–7)
- 5–8 проверяемых детекторов: внезапное изменение платы логистики; дубли начислений; SKU с отрицательным вкладом; рост рекламных затрат при ухудшении экономики; сверхдорогое хранение; расходы возвратов; эффекты акций; изменение цены/комиссии.
- Evidence Pack на каждый сигнал: строки, период, правило, версия, формула, ограничения и возможное пересечение.
- Статусы: DETECTED → VALIDATING → VERIFIED/REJECTED → PROPOSED → APPROVED → IMPLEMENTED → MEASURED.
- Opportunity score: консервативный ожидаемый прирост прибыли за вычетом возможной потери продаж, трудозатрат и затрат внедрения; дедупликация пересечений.
**Gate:** precision@5 ≥80% по ручной разметке (целевой тестовый порог); ни одной выдуманной суммы/правила; оценка в ₽ привязана к воспроизводимым данным.

### v0.4 — AI Advisor, guarded (недели 6–9)
- LLM переводит находки в язык предпринимателя: «что произошло / где доказательство / почему это гипотеза / действие / риск».
- LLM не меняет исходные данные, тарифные правила, маржу, кампании или цены.
- RAG по версиям публичных тарифов и клиентским данным, где есть права. Все новые рекомендации только на основе Financial Ledger.
- Regression тесты промпт-инъекций из текстов отчётов, отказ в произвольных действиях, схема JSON для output, уровень уверенности.
**Gate:** 0 произвольных финансовых чисел без источника в проверочном наборе; возможность открыть доказательство из интерфейса.

### v0.5 — Private Alpha (недели 8–11)
- 10–20 тестовых магазинов, только READ ONLY, загрузка отчётов, веб-интерфейс «3 главные потери сегодня», список действий.
- Самостоятельная себестоимость SKU, частичный режим с явным статусом данных, редактирование известных фактов владельцем.
- Оплачиваемый тест подписки 990 / 1 990 / 2 990 ₽ на желающих, без кастомной разработки.
**Gate:** ≥10 аудитов с ручной экспертизой; ≥5 реальных платежей без персональной продажи каждого; ≥60% клиентов достигли «первая проверенная находка» после подключения (гипотеза цели); нет критических security-багов.

## Стадия 2 — Distribution Product (январь — март 2027)

### v0.6 — Manager Workspace & Sharing
- Бесплатный кабинет для менеджера, приглашение владельца, разделение прав между магазинами и работодателями.
- Подписку оплачивает магазин; менеджер не видит данные иных клиентов без разрешения.
- White-label/совместный PDF-отчёт «3 возможности с проверкой», редактирование приватных полей, invite link владельцу.
- Партнёрская ссылка/код, выплаты после подтверждённой оплаты и исключения возврата, правила конфликта интересов.
**Gate:** ≥30 активных менеджеров, ≥15 приглашений владельцам, ≥5 оплаченных рекомендованных магазинов; никакой утечки данных между tenant.

### v0.7 — Partner Academy Kit
- Встроенный образовательный кейс для действующих менеджеров: «как за 15 минут найти факторы падения прибыли».
- Sandbox демоданные, задания с правильными ответами, выдача сертификата только после проверки.
- Отдельный кабинет партнёра: UTM, купон, атрибуция приглашений, конверсия в paid, доля продлений.
**Gate:** ≥2 образовательных партнёра реально опубликовали программу/приглашение; в каждой когорте измерены подключения и оплаты. Договорённость ≠ активная дистрибуция.

### v0.8 — Self-Service API Beta
- Production-интеграция READ ONLY к выбранной площадке, ключи/права/срок действия, автообновления, восстановление после ошибок.
- Затем вторая площадка: только после доказанной устойчивости первой.
- Данные сверяются с бухгалтерско-финансовыми отчётами; при несовпадении агент не утверждает точный эффект.
**Gate:** 90%+ успешных плановых загрузок без ручного вмешательства (целевой порог); понятные статусы ошибок; нагрузочное тестирование на 100 клиентов.

## Стадия 3 — Commercial Scale (апрель — июнь 2027)

### v0.9 — Public Beta / Billing
- 3 тарифа, self-service оплата, понятные лимиты по магазинам, SKU и интенсивности анализа.
- Billing, платежи, оферта/конфиденциальность/удаление данных, журнал аудита, восстановление после отказа.
- Активация и реферальная воронка, когортный churn, gross margin по тарифам, CAC по партнёрам.
**Gate:** ≥100 платящих и ≥2 оплаченных месячных периода для части когорты; net revenue retention и churn считаются из реальных событий; стоимость по каждому клиенту измерима.

### v1.0 — General Availability
- Полностью автономный еженедельный финансовый аудит + событие по критическим отклонениям.
- Подтверждённые кейсы по фактической экономии; библиотека детекторов расширена по частоте и ROI.
- Каналы поддержки и партнёров масштабируются только при положительной contribution margin и повторных оплатах.
**Gate:** ≥300 платящих, подтверждённая положительная маржа на каждом массовом тарифе; нет критических дефектов; партнерские когорты сохраняются.

## Стадия 4 — AI CFO & Network Effects (июль 2027 и далее)

### v1.1 — Profit Recovery Loop
- Трекер исполнения рекомендаций, контроль внедрения и доказанный post-action эффект.
- Прогноз потерь и сценарные калькуляторы с интервалами неопределённости.
- Режим «менеджер отвечает за 5–10 магазинов» с финансовыми сводками и безопасными ролями.

### v1.2 — Multi-Agent AI CFO
- Finance, Ads, Logistics, Pricing, Inventory, Risk; маршрутизация по сигналам и стоимости, не круглосуточные LLM-чаты.
- Tool calls строго allowlisted, budget limit на клиента, policy/risk engine, read-only до явного разрешения на будущие действия.
- Менеджерские плейбуки, RAG по тарифам и изменениям площадок, multi-seller ограничение доступа.

### v2.0 — Ecosystem / Extensions
- Дополнительные площадки после проверки API и спроса, integration partners, marketplace app stores, безопасный marketplace of playbooks.
- Вертикальные KPI по категориям, opt-in обезличенные бенчмарки при юридически допустимых условиях.
- Цель: 1 000+ платящих магазинов; расширение только после доказанного retention и channel economics.

## Стоп-условия
1. Финансовые данные не удаётся достоверно сверить — не показывать точную «потерю».
2. False positive не позволяет отличить выигрышную рекомендацию от вредной — остановить детектор.
3. В среднем переменная себестоимость >35% тарифа в устойчивой когорте — переработать архитектуру и лимиты.
4. Клиенты не повторяют оплату, даже получив несколько находок — проверять ценность постоянного мониторинга вместо новых агентов.
5. Partner CAC выходит за допустимую окупаемость либо реферальные рекомендации не приводят к 2-й оплате — прекращать канал.

# ОБНОВЛЕНИЕ v0.2 — UX/UI × 3 уровня зрелости × тарифы (18.11.2026)

**Статус:** design proposal / план работ, ничего не объявляется внедрённым. Базовые финансовые, AI и GTM-gates версий 0.1–2.0 выше остаются в силе. Этот блок уточняет scope и добавляет UX- и pricing-gates; он не заменяет прошлые критерии.

## Ключевое решение

- ОДНО финансовое ядро, один реестр операций, одни Evidence Packs и Opportunity Engine для всех планов.
- ТРИ режимa отображения: **«Начинаю»**, **«Контролирую»**, **«Развиваю»**. Это предпочтение, которое пользователь меняет в любой момент без оплаты. Доступ к первичным доказательствам универсален.
- ТРИ тарифa: **Старт 990 ₽**, **Контроль 1 990 ₽**, **Рост 2 990 ₽**. Сложность интерфейса не является платной функцией: оплачиваются число магазинов, частота и глубина вычислений, объём SKU, сценарные возможности, совместная работа и лимиты AI-запросов.
- ПЕРСОНЫ НЕ ТАРИФЫ: новичок вправе приобрести «Рост»; эксперт вправе остаться на «Старт» и выбрать простой экран. Это предотвращает путаницу и дискриминацию по навыкам.
- Один и тот же финансовый сигнал имеет три визуальных представления: 1) «Что случилось и что сделать», 2) «Факторы и первичные строки», 3) «Сценарии действий, риски, неопределённость и контроль эффекта».
- **Главное УТП** сохраняется: «Найдём, где ваш бизнес на Wildberries и Ozon теряет от 100 000 ₽ прибыли в месяц». Не показывать как всеобщую гарантию; для микроселлеров без достаточного оборота фактическая находка и прогнозная оценка индивидуальны. Требуется правовая и доказательная проверка публичной рекламы до размещения.

## Новый параллельный поток: Persona UX / Design System

### v0.1 — Discovery + UX Research
- Разметить 20 интервью по реальному финансовому workflow: N (начинаю), F (контролирую), G (развиваю). Не назначать сегмент только по обороту: платформа/число SKU/доступ к данным/роль существеннее.
- Карта JTBD, терминов («заказы», «поступления», «выкуп», «прибыль», «ДРР»), подходов к вводимой себестоимости, трёх критических вопросов каждой персоны.
- Проверить 3 набора задач на 5 респондентах каждого типа (итого целевые 15 UX-сессий, могут пересекаться с интервью).
- Каркас навигации, текстовые прототипы и унифицированные статусы DETECTED/VERIFYING/VERIFIED/REJECTED/IMPLEMENTED/MEASURED.
**UX-gate:** ≥4/5 участников в каждой группе верно отличают «найденный потенциал» от «полученной экономии» и понимают следующее действие без подсказки. Цель для теста, не факт.

### v0.2 — Onboarding + Data Health
- Маршруты: новичок (мастер себестоимости), финансист (импорт данных и сверка), оптимизатор (цель/риски/период и исходная база). Пользователь свободно меняет маршрут.
- «Паспорт данных»: дата обновления, полная/частичная экономика, недостающие поля и влияние пробела на достоверность.
- Простой FAQ: не приравнивать выплаты к прибыли, ДРР рекламный к общему, рекламу к доказанной инкрементальности.
**UX-gate:** новичок самостоятельно проходит импорт и фиксирует недостающую себестоимость, а финансовый пользователь самостоятельно находит источник расхождения.

### v0.3 — Opportunity Cards по уровням
- Одна находка, три режима detail density; в каждом доступны ссылка на первичный документ, расчёт, период, возможность отклонить и причина недостоверности.
- Обязательные суммы разнести на «потенциал за месяц», «разовый возврат», «подтверждённая экономия» без суммирования единиц измерения.
- Вход для новичка: максимум 3 верхних действия и план «сделай 1 шаг»; для финансиста: таблица, фильтры, drill-down по SKU; для оптимизатора: список по net effect, уверенность, риски и сценарии.
**UX-gate:** 0 вводящих в заблуждение сумм при контент-тесте и ревью 20 карточек.

### v0.4 — AI CFO explanatory layer
- Простые объяснения без терминов, детальный технический вариант и управленческая версия решения; ответ всегда связан с Evidence ID.
- Отдельное объяснение «почему рекомендация может не сработать», запрет фразы «мы сэкономили», пока статус не MEASURED.
- Ограничение длины, читабельность и расхода токенов в каждом тарифе.
**UX-gate:** качество ответов на 30 тестовых вопросов и отсутствие неподтверждённых чисел.

### v0.5 — Clickable alpha + pricing choice
- Кликабельный прототип, отдельные dashboard / opportunities / evidence / plan / pricing / onboarding / manager / settings.
- Проверка выбора режима, перехода тарифа, платежного paywall, доступности действий и мобильного экрана.
- Нет автоприменения цен, ставок, бюджетов и отправки обращений.
**UX-gate:** минимум 5 действующих продавцов проходят от импорта до чтения доказательства без помощи; отдельно измерить time-to-first-trusted-opportunity.

### v0.6 — Manager Workspace
- Роль менеджера независима от уровня аналитической зрелости и тарифа магазина. Бесплатный доступ только с явным владельческим приглашением.
- Создание обезличенной preview-карточки и приватной подробной карточки, разрешение/отзыв, реферальный invite без раскрытия коммерческих данных.
**UX-gate:** cross-tenant privacy и отзыв доступа проходят сквозные тесты; менеджер делится находкой, не присылая приватные цифры посторонним.

### v0.7 — Academy UX
- Sandbox из синтетических данных; учебные задания по каждому уровню и совместная работа «менеджер → владелец».
- Связка урок → мини-аудит → первая обоснованная находка → приватная рекомендация → подписка и атрибуция.
**UX-gate:** партнёр видит drop-off по каждому шагу, в том числе долю с подтверждённым первым результатом.

### v0.8 — Autopilot & Connectors
- Ясно различать «файл загружен», «данные не полны», «API недоступен», «расчёт заблокирован» и «аудит завершён».
- Управление правами и отзыв ключа, отмена тарифа, выгрузка и удаление данных доступны без обращения к поддержке.
**UX-gate:** 90% успешных циклов синхронизации и понятная recovery-схема для пропущенных данных.

### v0.9 — Public Beta
- Pricing/plan entitlements через единый feature registry; доступ к Evidence/исходникам не прятать за тарифом.
- Product analytics по persona × tier × acquisition channel, а не только общая воронка.
- A/B-test onboarding/tier explanation с заранее определённой гипотезой.
**UX-gate:** фактический activation/AHA rate, валовая маржа и повторная оплата по каждой из 9 комбинаций persona×tier.

### v1.0–1.2 — Adaptive UI + Growth Lab
- Рекомендовать интерфейсный режим на основании задач и действий, но не менять его принудительно.
- «Рост» получает эксперимент-план, safe guardrails, журнал исходных условий, сравнение до/после, метку уровня причинной уверенности.
- Логи и Explainability: кто/когда предложил/согласовал/внедрил, какой источниковый снимок использован.
**Gate:** повторная ценность подтверждается когортами, не только количеством созданных карточек.

### v2.0 — Persona intelligence
- Усложнение аналитики без новой навигационной системы, масштабирование локализаций/категорий/площадок и контроля доступности.
- Публичный кейс — только по явному разрешению и с раскрытием метода измерения.

## Новые продуктовые метрики
- **TTFV (Time to First Trusted Value)** — время до первой проверяемой полезной находки, а не до открытия дашборда.
- **AHA (trusted)** — доля подключившихся, которым показана хотя бы одна значимая и воспроизводимая находка, либо честный результат «не найдено / недостаточно данных».
- **Action adoption** — доля одобренных и выполненных пользователем корректирующих действий.
- **Measured benefit** — дополнительная маржинальная прибыль с учётом риска и противодействующих факторов; отдельно от потенциала.
- **Mode switch rate**, **comprehension score** (понимание вывода), **persona→tier distribution**, **tier contribution margin**, **paid month 2/3**, **manager→owner paid**.

## Межфункциональные зависимости
- UX не должен обещать расчёт, если Financial Ledger или полнота данных не позволяют его сделать.
- Growth не должен выдавать демо-цифры за показатели живого бизнеса.
- Тарифные ограничения должны применяться к вычислениям централизованно, но не скрывать результаты уже оплаченного аудита или свидетельства суммы.
- Обучение и рефералы должны быть встроены в продукт (shareable evidence), а не существовать отдельной рекламной задачей.
