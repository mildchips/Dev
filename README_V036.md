# AI Profit Office v0.3.6 — Financial Reconciliation / LOCAL

Версия расширяет v0.3.5: появился отдельный контур сверки финансовых начислений, экран «Сверка финансов», журнал источников, карантин и партии себестоимости. Старые CSV/XLSX-импорты, сценарии, локальный вход, vault и стоп сохранены.

**[Реализовано]** Сверка загруженного нормализованного отчёта с отдельным контрольным файлом по общей сумме, категориям и, когда предоставлена разбивка, отправлениям; дедупликация по исходным событиям между отчётами. Все денежные вычисления нового контура — целые копейки, в браузер суммы передаются строками.

**[Смоделировано]** WB: список отчётов, детализация по ID/периоду; Ozon: справочник типов, связи с отправлениями, последовательность получения номеров и идентификаторов отчётов реализации. Эти сценарии существуют только в ReportLab с `httpx.MockTransport` и явной маркировкой синтетического контракта. Их ответы не попадают в финансовый учёт.

**[Не проверено на реальном API]** Права ключей, реальные схемы финансовых строк, типы начислений, комиссии/знаки денежных полей WB, пагинация новых отчётов Ozon и сверка с настоящим ЛК. Автоматического преобразования ответов API в сверенные начисления нет. Новые маршруты отсутствуют в live allowlist.

**[Production TODO]** PostgreSQL/RLS, RBAC/MFA, KMS, распределённые очередь/quota/kill, проверка условий API и юридических требований. Эта версия — один оператор, только localhost.

## Установка на Mac M1 / Python 3.13

```bash
python3.13 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-lock.txt
python scripts/test_offline.py -q
python -m app.finance_cli
python -m app.local_auth init-password
bash start.sh
```

Открыть http://127.0.0.1:8765. Простой smoke интерфейса: `node scripts/frontend_smoke_v036.cjs`. Это проверка выполнения JS, не визуальный браузерный тест.

Фиксированный lock включает тестовые зависимости; собран и испытан на Linux Python 3.12.14/3.13.5. macOS/Apple Silicon не испытаны. Первое выполнение создаёт локальное хранилище, но не подключает кабинеты маркетплейсов.

## Проверка финансов через интерфейс

1. Создать магазин WB. Открыть «Сверка финансов».
2. Загрузить `examples/finance_v036/report_wb.json`: 10 искусственных операций, сначала статус «Данные в процессе проверки».
3. Загрузить `batch.json`: себестоимость партии SYN-B1 — 400 ₽/ед.
4. В контрольный отчёт загрузить `independent_control.json`: начисления 730 ₽; при совпадении статус «Сверено», вклад после учтённых расходов — 330 ₽. Чистая прибыль не рассчитывается.
5. Повторить импорт: новых событий не появится. Создать другой магазин: его данные изолированы.

Для магазина Ozon использовать `report_ozon.json` и тот же синтетический контроль/партию. Это наш нормализованный формат, а не образец реального JSON площадки. Не загружать необработанный ответ API под видом этого формата.

## Обновление с v0.3.5

Остановить приложение (Ctrl+C), сделать резервную копию **всей** папки `~/.ai_profit_office` в защищённое локальное место, распаковать код в новую папку, установить зависимости и запустить `python scripts/test_offline.py -q`. Не заменять пользовательскую базу демо-базой. При запуске создаются только новые таблицы; старые данные не переписываются. Ничего удалять или сбрасывать не требуется. Для отката остановить приложение и использовать старый код с резервной копией. Тесты миграции проверяют сохранность старых таблиц и повторную инициализацию.

## Остановка

Остановить веб-приложение Ctrl+C. Для блокировки интеграций из другого терминала:

```bash
source .venv/bin/activate
bash scripts/kill-all.sh
```

При компрометации ключ дополнительно отзывается в кабинете площадки. Stop блокирует будущие dispatch, но не отменяет уже отправленный запрос.
