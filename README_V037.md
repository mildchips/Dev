# AI Profit Office v0.3.7 — Security Foundation / LOCAL

Продукт для российских селлеров Wildberries и Ozon. Релиз сохраняет финансовое ядро v0.3.6 и добавляет **отдельную лабораторию многопользовательского доступа**, измерения нагрузки/восстановления и подробный гайд по административному запуску в РФ.

**Это не готовый публичный SaaS.** Финансовое приложение по-прежнему обслуживает одного локального оператора на 127.0.0.1:8765. Новые логины и роли относятся только к лаборатории на 127.0.0.1:8766. Их нельзя считать защитой старых финансовых маршрутов. Никакого переноса реальных данных в lab или публикации портов.

## Что появилось

- [Реализовано в lab] Отдельные пользователи/организации/магазины, роли owner/manager/auditor, сессии и CSRF, одноразовые приглашения по логину с TTL и store scope. Отзыв доступа останавливает задания делегата.
- [Реализовано в lab] Durable SQLite очередь synthetic_audit, идемпотентность, атомарный claim, аренда 30 секунд, fencing, ограничение 3 попыток, backoff/DEAD, tenant stop/resume.
- [Реализовано в lab] Зашифрованные согласованные снимки, восстановление в новый путь, integrity/FK checks. После restore все сессии/инвайты недействительны, делегаты выключены, организации остановлены, задачи paused.
- [Смоделировано] KMS wrap/unwrap и версия envelope; AES-GCM с AAD tenant/store/provider/version/key_id. FakeKMS только в тестах; облачного адаптера/vault нет.
- [Не проверено] Реальные API площадок, PostgreSQL/RLS, облачный KMS/IAM, публичная сеть/TLS/HA, macOS и визуальный браузерный сценарий.
- [Production TODO] MFA/IdP, объединение нового security perimeter с финансовым ядром, RLS всех сущностей/файлов/экспортов, распределённые квоты/очередь/stop, PITR/DR/нагрузка/пентест, фактические правовые документы.

## Лаборатория: два тестовых пользователя

Только вымышленные логины/названия. Пароли вводятся скрыто; не передаются аргументами и не отправляются в чат.

```bash
python -m saas_lab user synthetic-owner --owner
```

Дождаться сообщения «Пользователь создан». Затем выполнить отдельно:

```bash
python -m saas_lab user synthetic-manager
```

После создания менеджера отдельно запустить сервер:

```bash
python -m saas_lab.server
```

Открыть http://127.0.0.1:8766. Войти владельцем, добавить вымышленный магазин. В форме приглашения выбрать `synthetic-manager`, роль и магазин; скопировать одноразовый код. Выйти и войти менеджером, принять код. Менеджер видит только разрешённые магазины, не может создавать магазины/приглашения или менять stop. Аудитор имеет только просмотр. Для независимой организации создать второго `--owner`. Учётные записи создаёт только локальная CLI: публичной регистрации нет.

Создать тестовую задачу из карточки магазина. В другом терминале с активным venv выполнить:

```bash
python -m saas_lab worker-once
```

В интерфейсе нажать «Проверить задачу»: результат synthetic_audit, verified_profit=false. Внешних запросов нет. Отзыв менеджера выполняется владельцем по его user_id, отображаемому в личном кабинете. При перезагрузке страницы снова войти. Сессии — 30 минут; доступ принятого менеджера/аудитора — 24 часа. Поддержка/системные роли через браузер не выдаются. Восстановления пароля и смены владельца пока нет.

## Снимок и восстановление лаборатории

Lab хранит данные отдельно: `~/.aipo_saas_lab/lab.db`. Создать защищённую папку для копии; команда не перезаписывает существующие файлы.

```bash
mkdir -m 700 -p "$HOME/aipo-lab-backups"
python -m saas_lab backup "$HOME/aipo-lab-backups/synthetic-037.aipobak"
```

Пароль копии 16+ символов, хранить отдельно. Для восстановления остановить lab (Ctrl+C), выбрать **новый несуществующий** путь:

```bash
python -m saas_lab --db "$HOME/.aipo_saas_lab/restored-037.db" restore "$HOME/aipo-lab-backups/synthetic-037.aipobak"
python -m saas_lab.server --db "$HOME/.aipo_saas_lab/restored-037.db"
```

Войти владельцем и проверить состав данных. Все организации stopped; перед возобновлением сверить отозванные права/доступы. Делегаты выключены и в этой версии автоматически не восстанавливаются; их повторное включение требует будущего отдельного процесса review. Учётные записи владельцев и старые пароли находятся в снимке: production recovery потребует отдельной проверки личности/смены секретов. Lab backup **не копирует старое финансовое приложение или его vault**.

Для обновления финансового приложения остановить его и сохранить всю `~/.ai_profit_office` в защищённое место по прежнему runbook. Распаковать новый код в новую папку, установить lock, выполнить offline tests, затем запускать. Финансовая схема не менялась, destructive migration нет; `saas_lab` не открывает старую базу. Для отката использовать старый код и сохранённые данные. Старую папку до проверки новой не удалять.
